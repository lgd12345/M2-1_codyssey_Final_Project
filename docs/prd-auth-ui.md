# PRD: 로그인 + 에이전트 동작 확인 화면 (임시)

**최종 목적은 고객이 웹으로 넣은 민원을 에이전트에 전달해 해결 초안을 만드는 것이다.** 지금 만드는 화면은 에이전트가 동작하는지, 어떻게 동작하는지 확인하기 위한 **임시 화면**이며 민원 연동 구조가 되면 제거한다. 따라서 라우터·상태 관리 라이브러리·TypeScript 전환 없이 파일 하나로 최소한만 만든다.

실제 LLM 비용이 발생하므로 실행은 로그인한 사용자만 할 수 있다. 참고: `정처기예상문제`(서명 쿠키 세션, 설정·상태 화면).

## 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| 인증 방식 | 서버 세션 + `HttpOnly` 쿠키 | 토큰을 JS(localStorage)에 두지 않음 → XSS로 탈취 어려움 |
| 사용자 저장 | PostgreSQL `app_user` | 계정 1개 `.env` 방식을 DB 사용자로 확장 |
| 비밀번호 | `pwdlib[argon2]`(Argon2id) | 검증된 라이브러리, 직접 구현 안 함 |
| 세션 | 불투명 토큰, DB에는 SHA-256 해시만 저장, 7일 만료, 로그아웃 시 폐기 | DB가 유출돼도 세션 재사용 불가 |
| CSRF | `SameSite=Lax` + `X-CSRF-Token` + Origin 검사 | 쿠키 인증의 상태 변경 요청 보호 |
| 가입 | **공개 회원가입 없음.** CLI로만 계정 생성 | LLM 비용·악용 방지 |
| 로그인 제한 | DB 기록, 접속지 10분 5회 / 아이디 10분 10회 | 다중 프로세스에서도 유지 |
| 외부 인증 서비스(Clerk/Auth0 등) | 사용하지 않음 | 내부 도구에 외부 의존·비용 불필요 |
| 프런트 | React 단일 파일(`App.jsx`), 추가 의존성 없음 | 임시 화면. 쿠키 세션은 인증 SDK가 필요 없음 |

## 범위

1. **인증 백엔드(1단계)**: 마이그레이션 `003_auth`, 로그인/로그아웃/me, 보호 의존성, 계정 생성 CLI.
2. **에이전트 실행 API(2단계)**: 로그인 사용자 소유 `agent_run` 저장, 실행 시작/조회/이미지 제공. 다른 사용자의 실행·이미지는 404.
3. **임시 화면(완료)**: 로그인 + 질문 실행 + 결과. 결과에는 답변, 인용 출처, 에이전트가 연 원본 페이지 이미지와 함께 **도구 호출 순서·인자(검색어 등)·검색 경로별 상태**를 보여 준다. 실행 중에는 상태만 표시하고, 도구 내역은 완료 후 표시된다(실시간 스트리밍은 하지 않음).
4. ~~별도 구현 확인(서버 상태) 화면~~: 만들지 않는다. 필요한 정보는 실행 결과의 도구 내역으로 충분하다.

## 보안 불변 조건

- 비밀번호·세션 토큰·API 키는 로그, 응답, 테스트 출력에 남기지 않는다.
- 존재하지 않는 계정과 틀린 비밀번호는 같은 응답(문구·상태·대략적인 소요 시간).
- 로그인 성공 시 기존 세션을 폐기하고 새 세션을 발급한다.
- 비활성 계정은 기존 세션도 즉시 무효.
- 에이전트 실행 이력은 소유자만 조회한다.
- 이미지는 해당 실행에서 에이전트가 연 페이지만 제공한다.

## 제외

비밀번호 재설정 메일, 소셜 로그인, 관리자 UI, 다중 테넌트 권한 세분화.
